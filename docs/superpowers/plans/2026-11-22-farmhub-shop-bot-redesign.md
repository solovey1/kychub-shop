# FarmHub Shop — новый вид бота и живая анкета

> Executor: Sonnet. Читать с `2026-11-21-farmhub-shop.md` (Global Constraints) и spec. Затрагивает только
> бота (`app/presentation/telegram/**`, `assets/messages/**`) и `app/application/models/form_schema.py`.

**Goal:** бот перестаёт быть голым текстом: понятный «главный экран», эмодзи со смыслом, карточки товара и
заказа, анкета покупки — одна живая карточка вместо «Вопрос 1 из N». Поддержка: тикет создаётся только
после первого сообщения.

**Тесты не пишем.** Проверка: ruff, mypy (2 известные ошибки), pytest (паритет ключей ru/en/uk).

## Правила оформления

- Эмодзи — только в ftl (потом заменим на кастомные одним правкой текста), одно в начале строки или кнопки,
  каждое что-то значит. Не в середине фраз, не по два подряд.
- Набор (единый для всего бота):
  - разделы: 🛍 Каталог, 🔎 Поиск, 📦 Мои заказы, 💳 Пополнить, 💰 Баланс, 💬 Поддержка, 🌐 Язык,
    📱 Открыть приложение, 🧰 Кабинет исполнителя;
  - статусы заказа: 🧾 ожидает данных, 💵 оплачен, 🕓 в очереди, ⚙️ в работе, 🔍 на проверке, ✅ выполнен,
    ❌ не выполнен, ↩️ возвращён, 🚫 отменён;
  - действия: ✅ Оплатить / Подтвердить, ✏️ Изменить, ⏭ Пропустить, ↩️ Как в прошлый раз, ✖️ Отмена,
    🎟 Промокод, ⬅️ Назад, 🏠 Меню;
  - страны — флаг из кода страны (функция `flag(code)` из regional indicator, без таблицы).
- HTML: `<b>` для заголовков, `<blockquote>` для ответов анкеты и результата, `<code>` для копируемого.
- Кнопки: главное действие экрана `style="success"`, опасное `style="danger"`.

## Экраны

- **Главный экран** (`/start`, «🏠 Меню»): «👋 Привет, {name}!», строка «💰 Баланс: $X», строка про активные
  заказы («📦 В работе N» и ближайший срок, если есть исполнитель и `deadline_at`; нет активных — строки нет).
  Кнопки 2 в ряд: Каталог | Поиск, Мои заказы (N) | Пополнить, Поддержка | Язык; отдельной строкой
  «📱 Открыть приложение» (web_app, `app_button`), если есть https; у исполнителя «🧰 Кабинет исполнителя».
- **Категория:** заголовок, кнопки подкатегорий и товаров; у товара в кнопке цена «от $X».
- **Товар:** название, описание, «⏱ Срок: до N ч» (если есть сервис), выбор варианта кнопками
  «🇹🇷 Турция — $5», недоступные — `disabled`.
- **Живая анкета** (FSM): одно сообщение-карточка, редактируется после каждого ответа.
  ```
  🧾 <b>{product}</b>, {flag} {variant}, ${price}

  ✅ {label}: {value}
  ✏️ <b>{label}</b>
  ▫️ {label} (можно пропустить)
  ──────────
  {hint или «Введите {label}»}
  ```
  - Текущий вопрос: под карточкой кнопки — варианты (`choice`), «⏭ Пропустить» (необязательный),
    «↩️ Как в прошлый раз: {value}» (есть ответ по этому `key` в последнем заказе пользователя на этот же
    товар; значение до 24 символов в кнопке, скрытые от исполнителя поля тоже можно), «✖️ Отмена».
  - Подсказка в поле ввода: бот отправляет отдельное короткое сообщение с `ForceReply(input_field_placeholder=
    placeholder или label)` и удаляет его после ответа. Сообщение пользователя с ответом удаляется
    (`delete_message`, ошибки глотать). В чате остаётся только карточка.
  - Ошибка проверки: в карточке под вопросом строка «⚠️ {причина}», ответ не принят.
  - `file`: «📎 Отправьте фото или файл»; принятый — «✅ {label}: 📎 файл».
  - В `FormField` добавить необязательные `hint: dict[str, str] | None` и `placeholder: dict[str, str] | None`
    (i18n, до 200 и 64 символов). `pick_i18n` для вывода.
- **Чек** (та же карточка после последнего ответа):
  ```
  🧾 <b>Проверьте заказ</b>

  {product}, {flag} {variant}
  <blockquote>{label}: {value}
  ...</blockquote>
  💵 Цена: $5.00
  🎟 Скидка {CODE}: −$0.50
  ──────────
  <b>Итого: $4.50</b>, на балансе $42.50
  ```
  Кнопки: «✅ Оплатить $4.50» (success), «🎟 Промокод», «✏️ Изменить ответы» (список полей кнопками →
  вернуться к этому вопросу, потом снова чек), «✖️ Отмена». Не хватает денег — вместо «Оплатить»:
  «💳 Пополнить на $X» (сумма нехватки) и строка «⚠️ Не хватает $X».
  Товар без анкеты — сразу чек.
- **Заказ принят:** та же карточка становится «✅ Заказ №N оплачен» + что дальше («Ищем исполнителя» /
  «Выполняется»), кнопка «📦 Открыть заказ».
- **Карточка заказа:** заголовок «📦 Заказ №N», товар и вариант, сумма, затем ход выполнения по
  `OrderEvent` со временем: каждый пройденный шаг «✅ {шаг}, {HH:MM}», текущий «⚙️ {шаг}» (у «в работе» —
  «сдаст до HH:MM»), будущие «▫️ {шаг}». Исполнитель — `alias`. Кнопки: «💬 Написать исполнителю» (только
  assigned/ready), «🆘 Поддержка» (→ экран поддержки с привязкой к заказу), «🚫 Отменить заказ» (danger, только
  in_queue). Список заказов: «{статус-эмодзи} №N, {товар}, ${сумма}».
- **Заказ выполнен:** сообщение с `message_effect_id="5046509860389126442"` (🎉), результат в `<blockquote>`,
  копируемые строки кнопками `copy_text`, как сейчас.
- **Баланс:** «💰 Баланс: <b>$X</b>», последние 5 проводок с эмодзи по виду (➕ пополнение, ➖ покупка,
  ↩️ возврат, 🎁 бонус, 💝 чаевые), кнопки «💳 Пополнить», «🎟 Активировать промокод».
- **Поддержка** (меню или из заказа): тикет НЕ создаётся. Экран: «💬 <b>Поддержка</b>» + «Опишите вопрос, и
  менеджер ответит. Обычно в течение часа.» Кнопки «✍️ Написать в поддержку» и «✖️ Отмена». Нажатие:
  «Напишите вопрос одним сообщением» + «✖️ Отмена» (FSM-состояние). Первое сообщение → `open_ticket` →
  сообщение уходит в тикет → «✅ Отправлено. Ответ придёт сюда, переписка — в приложении» + «Открыть чат».
  Есть открытый тикет — экран «У вас открыт тикет №N» + «Открыть чат» + «✖️ Закрыть». Отмена — назад в меню,
  ничего не создано. `open_ticket` больше не вызывается по кнопке меню.
- **Кабинет исполнителя и уведомления персоналу/исполнителю** — те же правила: эмодзи статусов, флаги,
  «💵 Вы получите $X», «⏱ Срок до HH:MM», главное действие success.
- Копирайт: коротко, от пользователя, без канцелярита («Заказ найден», а не «Ваш заказ был успешно найден»).
  ru/en/uk — все три.

## Review Focus

1. Удаление сообщений и редактирование карточки не падают, если сообщение уже удалено/старше 48 ч: глотать
   `TelegramBadRequest`, при невозможности редактировать — отправить карточку заново и запомнить новый id.
2. «Как в прошлый раз» берёт ответ только из заказов этого же пользователя.
3. Анкета, начатая, но брошенная, не мешает другим кнопкам: любое нажатие меню сбрасывает FSM.
4. Покупка из чека идёт через тот же `PurchaseInteractor` с тем же токеном идемпотентности: двойной тап
   «Оплатить» — один заказ.
5. Тикет не создаётся при отмене, создаётся ровно один при первом сообщении.
