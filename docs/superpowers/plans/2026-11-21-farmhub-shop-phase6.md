# FarmHub Shop — Фаза 6: поддержка и переписка

> Executor: Sonnet. Читать вместе с `2026-11-21-farmhub-shop.md` (Global Constraints) и spec §9, §15
> (маршрутизация сообщений), §8 п.4 (анонимность переписки с исполнителем).

**Goal:** тикеты поддержки с закреплением за первым взявшим менеджером; анонимная переписка покупатель ↔ исполнитель
внутри заказа; вся переписка хранится; сообщения покупателя маршрутизируются по правилам §15, лишнее отбрасывается.
Работа менеджера в этой фазе — в боте; Mini App (фаза 8) покажет ту же историю.

**Тесты не пишем.** Проверка: ruff, mypy (2 известные ошибки), `import app.__main__`, dishka-граф.

## Решения

- Миграция `003_conversations_unique.py` (вручную): уникальный частичный индекс `conversations(order_id)
  WHERE kind = 'order'`, уникальный индекс `conversations(ticket_id)`.
- Роль менеджера: админ-команды `/manager_add <tg_id>`, `/manager_del <tg_id>` (как `/executor_add`: создать
  заготовку пользователя, если нет; `AuditLog`).
- `ConversationInteractor` (application, без aiogram):
  - `open_ticket(user_id, order_id: int | None) -> tuple[Ticket, Conversation, bool]` — есть открытый
    (`open|taken`) тикет пользователя по этому же заказу (или общий при `None`) → вернуть его, `created=False`.
    Заказ должен быть его.
  - `take_ticket(manager_id, ticket_id) -> bool` — под блокировкой тикета: `open` и `manager_id IS NULL` → `taken`.
  - `close_ticket(actor_id, ticket_id)` — менеджер тикета, админ или сам пользователь.
  - `order_conversation(order_id) -> Conversation` — get-or-create `kind=order`.
  - `participants(conversation) -> Participants(buyer_id, counterpart_id | None, counterpart_role)`:
    тикет — менеджер тикета (`None`, если не взят); заказ — текущий `order.executor_id`.
  - `can_post(user_id, conversation) -> Role | None` — покупатель, текущий исполнитель заказа, менеджер тикета,
    админ. Иначе `None`.
  - `post(conversation_id, sender_id, text: str | None, media: dict | None) -> Posted` — сначала сохранить `Message`
    (commit), потом вернуть, кому доставить. Хранится всегда, даже если доставка упадёт.
  - `record_delivery(message_id, tg_chat_id, tg_message_id)` — id копии у получателя (для ответа реплаем).
  - `find_by_reply(tg_chat_id, tg_message_id) -> Conversation | None`.
  - `history(conversation_id, limit=20)`.
- Анонимность: исполнитель видит «Покупатель · заказ №N», покупатель видит `alias` исполнителя, у тикета покупатель
  видит «Поддержка», менеджер видит имя пользователя и номер тикета. Ни username, ни id покупателя исполнителю.
- Доставка — в `Notifier`/отдельном `Relay` (infrastructure/telegram): текст → `send_message` с заголовком-строкой;
  медиа → `copy_message` с подписью = заголовок + исходная подпись; типы без подписи (стикер, кружок) — сначала
  строка-заголовок, потом `copy_message`. В `Message.media` хранить `{"type", "file_id"}`. Под каждой доставленной
  копией кнопка «Ответить» (ставит текущую переписку).
- Маршрутизация (роутер `handlers/main/relay.py`, личка, не команда, **последний** в цепочке, только при пустом FSM):
  1. `reply_to_message` → `find_by_reply` → если `can_post` — в эту переписку.
  2. Текущая переписка из Redis (`ActiveConversationKey(user_id)`, TTL 30 мин, ставится кнопками «Написать» /
     «Ответить», продлевается при каждом сообщении) → если `can_post` — в неё.
  3. Иначе — отбросить; подсказка «Чтобы написать по заказу или в поддержку, откройте заказ или нажмите
     «Поддержка» в меню» не чаще раза в час (флаг в Redis).
  Темы в личке (правило 3 из spec) не делаем: тем бот пока не создаёт.
- Уведомления менеджерам: новый тикет → всем `MANAGER`/`ADMIN` в личку: №, пользователь, заказ (если есть),
  первое сообщение, кнопка «Взять» (`success`). id сообщений — в Redis (`TicketOfferKey`), после `take` остальным
  — «Взял <имя менеджера>». Сообщения пользователя в невзятый тикет только сохраняются; взявший менеджер получает
  историю (последние 20) сразу после «Взять».
- Покупатель без исполнителя в заказе пишет «Написать исполнителю» → кнопки нет, пока `executor_id` пуст.
  При смене исполнителя переписка остаётся, старый исполнитель писать больше не может (`can_post`).
- Кнопки: главное меню «Поддержка» → `open_ticket(None)` + текущая переписка + «Напишите ваш вопрос»;
  экран заказа покупателя: «Связаться с поддержкой», «Написать исполнителю» (если назначен); экран заказа
  исполнителя: «Написать покупателю»; у менеджера под сообщением: «Ответить», «История», «Закрыть тикет».
- Поддерживаемые типы: text, photo, document, video, voice, audio, animation, sticker, video_note. Остальные —
  «Этот тип сообщений не поддерживается».

## Review Focus

1. Реплай на старое сообщение исполнителя, с которого заказ уже снят → отказ, сообщение никуда не ушло.
2. Два менеджера жмут «Взять» одновременно → тикет у одного.
3. Сообщение без текущей переписки и не реплай → отброшено с подсказкой, подсказка не спамит.
4. Пользователь в середине анкеты покупки пишет текст → идёт в анкету, не в переписку.
5. Доставка упала (получатель заблокировал бота) → сообщение сохранено в истории.
