# FarmHub Shop — Фаза 8: фронтенд Mini App

> Executor: Sonnet. Читать вместе с `2026-11-21-farmhub-shop.md` (Global Constraints), spec §11, §15a и
> `2026-11-21-farmhub-shop-phase7.md` (API). Контракт API — `app/presentation/fastapi/api/schemas.py`.

**Goal:** Mini App в каталоге `webapp/` (React + Vite + TypeScript), три рабочих места на одном API:
покупатель (заказы, баланс, «мои исполнители», чаты заказа и поддержка), исполнитель (очередь, свои заказы,
сдача результата, кошелёк, рейтинг), персонал (тикеты, заказы на подтверждение). Покупки — только в боте.
Админка каталога — фаза 9.

**Тесты не пишем.** Проверка: `npm run build` (внутри `tsc --noEmit`, strict) без ошибок; `vite dev` в режиме
моков, скриншоты каждого экрана в светлой и тёмной теме через Browser pane, ширина 375 px; бэкенд — ruff, mypy
(2 известные ошибки).

## Зависимости

`react`, `react-dom`, `wouter` (роутинг, hash-location), `@fontsource-variable/onest`. Dev: `vite`,
`@vitejs/plugin-react`, `typescript`, `@types/react`, `@types/react-dom`. Больше ничего: ни UI-кита, ни
state-менеджера, ни Telegram SDK-обёрток (`telegram-web-app.js` подключается тегом `<script>` в `index.html`,
типы — свой маленький `telegram.d.ts` только на то, что используем).

## Дизайн

Направление: приложение должно выглядеть частью Telegram, а не сайтом внутри него. Своё лицо — в одном месте:
**трек заказа** и денежные суммы.

- **Цвета.** Фон, текст, подсказки, секции, кнопки — только переменные темы Telegram
  (`--tg-theme-bg-color`, `--tg-theme-secondary-bg-color`, `--tg-theme-text-color`, `--tg-theme-hint-color`,
  `--tg-theme-button-color`, `--tg-theme-button-text-color`, `--tg-theme-destructive-text-color`,
  `--tg-theme-section-separator-color`), с fallback на светлую тему. Свой цвет один: `--usdt: #26A17B`
  (цвет Tether) — им пишутся зачисления (+$) и закрашивается пройденная часть трека. Ни градиентов, ни теней.
- **Шрифт.** Onest Variable (кириллица, self-hosted через fontsource) для всего. Суммы:
  `font-variant-numeric: tabular-nums`, баланс на экране «Баланс» — 40 px / 600, знак `$` того же кегля,
  на 40% прозрачности. Шкала: 13 / 15 / 17 / 22 / 40, межстрочный 1.35 для текста.
- **Раскладка.** Одна колонка, отступ 16 px. Списки — группы строк на `secondary-bg` со скруглением 12 px и
  разделителями `section-separator` (как настройки Telegram), не отдельные карточки. Заголовок группы —
  обычный регистр, 13 px, цвет `hint`. Нижняя панель вкладок по ролям (см. ниже), 56 px + safe-area.
- **Трек заказа** (подпись приложения): горизонтальная линия из шагов `оплачен → в очереди → в работе →
  проверка → выполнен` (для `stock|fixed|manual` — только `оплачен → выполнен`). Пройденное — `--usdt`,
  текущий шаг — точка с кольцом, остальное — `hint`. `cancelled|failed|refunded` — линия обрывается на
  последнем достигнутом шаге, в конце метка статуса цветом `destructive`. Это единственная анимация
  приложения: при смене статуса по WebSocket линия дорастает до нового шага за 400 мс (`prefers-reduced-motion`
  — без анимации).
- **Нативные элементы Telegram:** главное действие экрана — `MainButton` (Взять заказ, Сдать результат,
  Подтвердить, Отправить в чате не надо — там своя кнопка у поля ввода), назад — `BackButton`,
  подтверждения опасных действий — `showConfirm`, ошибки — `showAlert`, успех действия — `HapticFeedback
  .notificationOccurred("success")`. `expand()` и `ready()` на старте; `setHeaderColor("secondary_bg_color")`.
- **Нельзя:** эмодзи в интерфейсе, капс в подписях, `·` как разделитель метаданных, моноширинный шрифт
  для подписей, `→` в тексте кнопок, скелетоны с переливом, анимация появления каждого блока.
- Копирайт короткий, от пользователя, sentence case. Пустой список — что сделать дальше («Заказов пока нет.
  Каталог — в боте»). Ошибка — что случилось и что делать, без извинений.

## Решения

- **Структура:**
  ```
  webapp/
    index.html            # <script src="https://telegram.org/js/telegram-web-app.js">
    vite.config.ts        # base "/app/", dev proxy /api -> http://localhost:8080 (ws: true)
    src/main.tsx, App.tsx # провайдер me, вкладки, роуты
    src/telegram.ts       # WebApp: initData, theme, MainButton/BackButton хуки, haptics
    src/api.ts            # fetch-обёртка, типы ответов (руками по schemas.py), ApiError{status, code}
    src/live.ts           # WebSocket: auth-кадр, переподключение, подписки по типу события
    src/i18n/{ru,en,uk}.ts, index.ts
    src/ui/               # Section, Row, Track, Money, Tabs, Empty, Chat
    src/screens/{buyer,executor,staff}/...
    src/dev/mock.ts       # только DEV: фикстуры вместо fetch
  ```
- **API-клиент:** каждый запрос с `Authorization: tma ${WebApp.initData}`. 401 → экран «Сессия устарела,
  откройте приложение из бота заново» (кнопка `WebApp.close()`). 404 → «Не найдено». Деньги приходят строкой —
  никогда не парсить во float, только форматировать (`$12.50`, отрицательные `−$3.00` с настоящим минусом).
  Время — `Intl.DateTimeFormat` на языке пользователя, локальная зона.
- **Медиа в чате:** `<img src>` не несёт заголовок — картинки грузить `fetch` с авторизацией → `blob:` URL
  (освобождать `URL.revokeObjectURL` при размонтировании). Не-картинки — строка «Файл · тип» без скачивания
  (кроме `video`/`voice`/`audio` — тот же blob в `<video>`/`<audio>`).
- **Live (`live.ts`):** один сокет на приложение, `/api/ws` (в dev через proxy). Первый кадр
  `{"type":"auth","init_data": WebApp.initData}`. Закрытие 4401 — не переподключаться (сессия устарела);
  4409 — не переподключаться (открыто в другом месте); иначе переподключение с задержкой 1, 2, 4… до 30 с.
  Подписки: `message` → дописать в открытый чат (дедуп по `id`), `order` → обновить заказ/список,
  `queue` → перезапросить очередь, `ticket` → перезапросить тикеты. `ping` игнорировать.
- **i18n:** словари TS-объектами, `en` и `uk` типизированы как `typeof ru` — расхождение ключей = ошибка сборки.
  Язык — `me.language`, до ответа — `WebApp.initDataUnsafe.user.language_code` (ru/uk/en, иначе en).
  Подстановки `{name}` простым replace, множественное число — `Intl.PluralRules`.
- **Вкладки по ролям** (`me.roles`): всем — «Заказы», «Баланс»; `executor` — «Работа»; `manager|admin` —
  «Поддержка». Внутри «Работы» и «Поддержки» — сегменты сверху.
- **Экраны покупателя:**
  - Заказы: список (`GET /api/orders?page=`, «Показать ещё»), строка: продукт, вариант/страна, сумма, статус.
  - Заказ: трек, сумма, исполнитель (`executor_alias`), результат (если `completed`: каждая строка с кнопкой
    «Скопировать», `result_files > 0` → «Файлы — в чате с ботом»), «Отменить заказ» (если `can_cancel`,
    через `showConfirm`), «Написать исполнителю» (если есть alias), «Связаться с поддержкой».
  - Баланс: большая сумма, «Пополнить в боте» (`WebApp.close()`), история проводок (`kind` → текст из словаря).
  - Мои исполнители: alias и число выполненных для него.
  - Поддержка без заказа: кнопка в «Заказах» сверху → `POST /api/support` → чат.
- **Чат** (общий компонент): `GET .../messages` (подгрузка старых при прокрутке вверх по `before_id`),
  отправка `POST` (до 4000, счётчик с 3500), отправленное — сразу в ленту из ответа. Отправитель — по
  `sender_role` из словаря (покупатель / исполнитель / поддержка / администратор), своё справа. `can_post=false`
  → поле ввода заменено строкой «Переписка закрыта». 409 на отправку → то же. Клавиатура не перекрывает поле
  (`viewportStableHeight`).
- **Экраны исполнителя** (вкладка «Работа», сегменты «Очередь», «Мои», «Кошелёк»):
  - Очередь: продукт, страна, заработок, срок в минутах. Открыть → карточка, `MainButton` «Взять заказ»; 409 →
    `showAlert` «Заказ уже взят или недоступен» и обновить очередь.
  - Мой заказ: трек, срок (обратный отсчёт до `deadline_at`, раз в минуту), поля анкеты (`is_file` → «Файл — в
    боте»), «Написать покупателю», «Отказаться» (`showConfirm`). Если есть `result_form` — форма по схеме
    (`text`/`textarea`/`select` по `options`/`email`/`number`; `file` — подпись «Этот файл сдаётся в боте» и
    форма не отправляется, пока он `required`), `MainButton` «Сдать результат»; 422 → подсветить поле.
  - Кошелёк: «В холде», «Доступно», минимум вывода, адрес (редактирование, `PUT /wallet`), «Вывести»
    (`showConfirm` с суммой и адресом); рейтинг (`/stats`) — блок на этом же экране.
- **Экраны персонала** (вкладка «Поддержка», сегменты «Тикеты», «Проверка»):
  - Тикеты: сегмент `open | mine` (+ `all` для админа), строка: №, имя, заказ, время. Открыть → чат;
    невзятый — `MainButton` «Взять тикет» (409 → alert), свой — «Закрыть тикет» в меню чата (`showConfirm`).
  - Проверка: `GET /api/staff/orders?status=ready` → карточка (`/staff/orders/{id}`: все поля анкеты, включая
    скрытые от исполнителя, результат) → `MainButton` «Подтвердить», «Вернуть исполнителю» (поле комментария),
    «Провал и возврат» (`showConfirm`, цвет `destructive`). После действия — haptic и назад к списку.
- **Dev-моки** (`src/dev/mock.ts`): при `import.meta.env.DEV && !WebApp.initData` — подмена `fetch` фикстурами
  на все эндпоинты выше (пользователь со всеми тремя ролями, заказы во всех статусах, чат с картинкой), сокет не
  открывается. В прод-сборку не попадает (динамический импорт под `import.meta.env.DEV`). Без моков и без
  `initData` — экран «Откройте приложение из бота».
- **Бэкенд (мелкие правки этой фазы):**
  - `User.name` хранится уже html-экранированным; React экранирует сам → в API отдавать `html.unescape(name)`
    (`MeOut.name`, `TicketOut.buyer_name`).
  - `.gitignore`: `webapp/node_modules`, `webapp/dist`. `Makefile`: цель `webapp` (`npm ci && npm run build`
    в `webapp/`). `Dockerfile`: стадия `node:24-slim` собирает `webapp/dist` и копирует его в финальный образ.
  - README: как собрать фронт, URL `SERVER_URL/app/`, для разработки — HTTPS-туннель на `SERVER_PORT`.

## Review Focus

1. `initData` нигде не уходит в URL (ни в WS, ни в картинки), только заголовок и первый кадр сокета.
2. Экран исполнителя не показывает ни одного поля, которого нет в API (никаких данных покупателя из кеша
   других экранов).
3. Деньги ни разу не проходят через `parseFloat`/`Number` для расчётов.
4. Тёмная тема Telegram: весь текст читаем, нет захардкоженных светлых цветов кроме `--usdt`.
5. Двойной тап по `MainButton` («Взять», «Подтвердить», «Вывести») — второй запрос не уходит, пока идёт первый
   (`showProgress` + флаг).
