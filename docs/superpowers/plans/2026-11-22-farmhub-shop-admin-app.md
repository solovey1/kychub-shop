# FarmHub Shop — Фаза 9: админка в Mini App

> Executor: Sonnet. Читать с `2026-11-21-farmhub-shop.md`, spec, `-phase7.md`, `-phase8.md`,
> `2026-11-22-farmhub-shop-webapp-unread.md`. Делать после фазы «unread» и редизайна бота (поля `hint` и
> `placeholder` в `FormField` уже есть).

**Goal:** всё управление магазином — в Mini App, без команд: каталог и склад, сервисы и страны, исполнители
и менеджеры, пользователи и балансы, заказы (включая ручное назначение исполнителя), выводы, промокоды,
настройки, рассылки, статистика, журнал действий, передача тикетов. Команды бота остаются как запасной путь.

**Тесты не пишем,** кроме денег: если появится новая денежная операция (отклонение вывода), один тест в
`tests/application/` на повторный вызов без второй проводки (по образцу `test_ledger_db.py`). Проверка: ruff,
mypy (2 известные ошибки), pytest, `npm run build`, скриншоты экранов в моках (375 px, светлая и тёмная).

## Общие решения

- **Права.** `OWNER` и `ADMIN` — всё. `MANAGER` видит разделы по флагам: `CAN_CATALOG` (каталог, склад,
  сервисы, страны), `CAN_FINANCE` (балансы, выводы, промокоды, статистика денег), `CAN_USERS` (пользователи,
  исполнители, менеджеры), `CAN_BROADCAST` (рассылки). Заказы и тикеты — всем `MANAGER|ADMIN`. Настройки и
  журнал — только `ADMIN`. API: зависимость `require_perm(Role.CAN_X)` (ADMIN/OWNER проходят всегда), 403.
  Выдавать роли `ADMIN`/`OWNER` через UI нельзя (только `COMMON_OWNER_IDS`); флаги `CAN_*` и `MANAGER`,
  `EXECUTOR` — может ADMIN.
- **Журнал.** Каждое изменяющее действие пишет `AuditLog` (кто, что, id, краткий diff) в той же транзакции.
- **API** под `/api/admin/...`, роутеры `app/presentation/fastapi/api/admin/{catalog,people,orders,money,
  promo,settings,broadcasts,stats,audit}.py`. Логика — в интеракторах `app/application/interactors/admin/`,
  переиспользовать существующие (`ExecutorAdminInteractor`, `ManagerAdminInteractor`,
  `BalanceInteractor.admin_topup`, `OrderReviewInteractor`, `DispatchInteractor`). Деньги строкой, i18n-поля
  — `{ru, en, uk}`, `ru` обязателен.
- **Mini App:** вкладка «⚙️ Админка» (видна при любом праве), внутри — список разделов по правам. Формы —
  нативные `input`/`select`/`textarea`, сохранение — `MainButton` «Сохранить», удаление — `showConfirm`.
  Поля на трёх языках — три поля подряд с подписью языка, `ru` обязателен. Стиль — как в фазе 8.
- Удаление: категорию/товар/вариант/сервис, у которых есть заказы или дети, не удалять — только
  выключать (`is_active=false`), API отвечает 409 с понятным `code`.

## Разделы

### 9.1 Каталог (`CAN_CATALOG`)
- **Категории:** дерево (любая глубина), создать/переименовать/переместить (родитель)/порядок (стрелки
  вверх-вниз, `position`)/вкл-выкл/удалить пустую.
- **Товары:** список в категории, карточка: категория, сервис (для `executor`), названия и описания i18n,
  тип выдачи (`stock | fixed | manual | executor`) и его настройки (как ожидает реестр
  `app/application/fulfillment/`), вкл-выкл, порядок.
- **Конструктор анкеты** (`input_schema`) и **результата** (`result_schema`): список полей, у поля —
  `key` (генерировать из ru-подписи транслитом, редактируемый), тип, подписи i18n, `hint`, `placeholder`,
  обязательное, варианты (для `choice`), regex, `max_length`, «скрыть от исполнителя». Порядок стрелками.
  Перед сохранением — `FormSchema.model_validate` на сервере, ошибка → 422 с полем.
- **Варианты:** страна (из справочника) или без страны, название i18n (необязательное), цена, вкл-выкл.
- **Склад** (для `stock`): число непроданных по варианту, «Добавить» — textarea, одна строка = одна единица
  (пустые строки пропускать, дубли внутри вставки убирать), «Безлимитная единица» для `is_unlimited`,
  список последних 50 непроданных с удалением.
- **Сервисы:** код, название, срок (мин), режим (`queue | auto`), процент исполнителя, вкл-выкл.
- **Страны:** код ISO-2, названия i18n.

### 9.2 Люди и заказы
- **Пользователи** (`CAN_USERS`): поиск по id, @username, имени; карточка: имя, язык, дата, роли и флаги
  (переключатели), баланс (`CAN_FINANCE`: «Начислить / списать» с комментарием →
  `admin_topup`/`admin_adjust`, идемпотентность — токен из клиента `uuid`), последние заказы.
- **Исполнители** (`CAN_USERS`): список (alias, активен, в работе, выполнено, рейтинг), «Добавить» по
  Telegram ID + alias, карточка: вкл-выкл, лимит параллельных, процент (пусто = из сервиса), матрица допусков
  сервис × страна (чекбоксы), статистика, кошелёк (только просмотр).
- **Менеджеры** (`CAN_USERS`): список, добавить по Telegram ID, убрать, флаги `CAN_*`.
- **Заказы** (все `MANAGER|ADMIN`): список с фильтрами (статус, товар, покупатель id, исполнитель),
  карточка: всё о заказе (анкета полностью, результат, события с временем, проводки по заказу, исполнитель,
  покупатель), действия по статусу: «Назначить исполнителя» (in_queue/assigned: выбрать из активных
  исполнителей с допуском, новый `DispatchInteractor.assign(actor_id, order_id, executor_id)` — под
  блокировкой заказа, как `take`, но без проверки лимита; со старого — событие `reassigned`, уведомления
  обоим), «Подтвердить», «Вернуть исполнителю», «Провал и возврат», «Отменить с возвратом» — существующие
  интеракторы.
- **Тикеты:** передать другому менеджеру (`ConversationInteractor.hand_over(actor_id, ticket_id,
  manager_id)`; ADMIN — любой тикет, MANAGER — свой; уведомление новому).

### 9.3 Деньги, промо, рассылки, статистика, настройки, журнал
- **Выводы** (`CAN_FINANCE`): список `pending` (исполнитель, сумма, адрес с `copy`), «Выплачено» (поле
  tx-хеша → `paid`), «Отклонить» (причина → `rejected` + возврат `executor_available +amount`, вид
  `withdrawal`, `ref=f"withdrawal:{id}:reject"`, одна транзакция под блокировкой строки вывода; повтор —
  ничего). Уведомление исполнителю.
- **Промокоды** (`CAN_FINANCE`): список, создать/изменить/выключить; все поля модели `PromoCode`
  (скидка % или $, бонус, лимит, срок, товар, мин. сумма, только новым, список user id, многоразовый),
  проверка «ровно один из: % / $ / бонус» на сервере, использование (кто и когда).
- **Рассылки** (`CAN_BROADCAST`): текст (HTML Telegram, до 4096), «Отправить себе» (предпросмотр), «Запустить»
  (`showConfirm` с числом получателей). Отправка — задача планировщика, 25 сообщений/с, `TelegramRetryAfter`
  уважать, заблокировавшие бота пропускать и ставить `blocked_at`; прогресс `sent/failed` в карточке,
  «Остановить». Медиа не делаем.
- **Статистика** (`ADMIN` или `CAN_FINANCE`): за 1/7/30 дней — выручка (сумма `purchase`), пополнения, заказы
  по статусам, топ-10 товаров, выплачено исполнителям, сумма в холде и доступно у исполнителей, балансы
  покупателей всего. Таблицы и числа, без графиков-библиотек (если нужен график — простые CSS-столбики).
- **Настройки** (`ADMIN`): `hold_days`, `review_delay_hours`, `min_withdrawal` — числа с проверкой диапазона.
- **Журнал** (`ADMIN`): последние 200 записей, фильтр по актору и действию.

## Review Focus

1. Менеджер без флага не получает данные раздела ни через UI, ни прямым запросом (403).
2. Назначение исполнителя вручную на заказ, который в этот момент взял другой, — одно назначение
   (блокировка заказа), второй запрос → 409.
3. Отклонение вывода дважды — деньги вернулись один раз.
4. Нельзя удалить то, на что ссылаются заказы; выключенный товар пропадает из каталога и поиска.
5. Импорт склада: 1000 строк за раз работает, дубли не создаются, пустые строки не становятся единицами.
